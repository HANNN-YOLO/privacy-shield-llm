NLP Integration
Today, I am integrating NLP—using spaCy and Presidio—into the final pipeline. I am designing the final workflow with the following sequence: [Request (Front-End) -> Regex -> Presidio/spaCy -> Analyze -> RecognizerResult -> entity_process (from patient_detector, doctor_detector, address_detector, context_detector) -> resolver -> mapper(operation_config) -> anonymizer (redact) -> redact_service (business logic) -> return response]. Previously, I wrote detector code (for patients, doctors, addresses, and context) using Presidio that outputted a dictionary, and I tested this on the back-end using Postman. Now, to integrate these detectors into the final pipeline—which utilizes Presidio's _analyze_ and _anonymization_ (redaction) functions and produces a _RecognizerResult_—I need to refactor my detector code. I am changing the output format from a dictionary to a _RecognizerResult_ or a class object. The next step is _entity_process_: if the _analyze_ result is an entity like PERSON, _entity_process_ converts it to PATIENT or DOCTOR; if it is LOC or GPE, it converts it to ADDRESS; meanwhile, medical terms (diseases) are skipped, as I have already created custom detectors to handle patients, doctors, addresses, and context. Next is the _resolver_ stage to handle duplicates or option selection; for instance, if a PERSON entity is converted into a PATIENT, the _resolver_ selects one (e.g., discarding PERSON and keeping PATIENT). The subsequent step is the _mapper_ to map the _RecognizerResult_ with my detectors within a single text, followed by the _anonymizer_ to perform text redaction, and finally calling the Presidio function within the _redact_service_. Thus, my _redact_service_ now invokes both Regex and Presidio and sends the response to the front-end. Evidence of this implementation can be found in the images section of the "Week 3" folder under the filename "Final Pipeline.png".

Redaction Pipeline Explanation

The redaction process starts from the Front-End, where the user submits clinical text. The text is first processed by the Regex detectors for Email, Date, Phone, and ID.

The detected entities are then combined with the results generated by Presidio. Presidio produces RecognizerResult objects that are subsequently passed to the Entity Processor.

The Entity Processor applies the custom NLP detectors:

Patient Detector
Doctor Detector
Address Detector

The resulting entities are passed to the Resolver, which determines which entities should be retained when overlapping detections occur.

After resolution, the entities are passed to the Normalizer, which groups entities based on their type and value while preserving their occurrences.

The final entities are then passed to the Pseudonymizer, which generates tokens and stores the mapping through the Mapping Service into Redis.

Finally, the Metrics Service calculates the estimated PHI/PII entities and processing duration before the result is returned to the Front-End.

The restore process follows a separate pipeline because it does not perform entity detection again. Instead, it extracts the pseudonymization tokens and retrieves their original values from Redis.

Restore Pipeline Explanation

The restore process begins when the Front-End sends a restore request.

The request is handled by restore_service.py, which extracts the pseudonymization tokens from the submitted text.

The extracted tokens are passed to the Mapping Service, which retrieves the corresponding original values from Redis.

The retrieved mappings are then used to reconstruct the original text. The restored entities are subsequently passed to the Metrics Service to calculate the restoration metrics and processing duration.

The final result is returned through restore.py using the defined response schema and displayed on the Front-End.
